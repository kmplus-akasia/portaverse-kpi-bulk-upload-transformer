4. Spesifikasi Converter Terbaru

4.1 Input yang diproses

Converter menerima input berikut untuk setiap group:

  • Source workbook atau ZIP workbook Kamus KPI Group 1 HO V2, Group 2, atau Group 3.
  • Template upload resmi input/KPI Upload Template.xlsx.
  • Reference organisasi terbaru output/production_position_reference_20260623_latest.json.
  • Config discovered yang dibuat converter, plus override hasil review jika sudah ada.

4.2 Workbook discovery dan sheet selection

Untuk ZIP batch, script mengekstrak semua file .xlsx selain temporary Excel seperti ~$.... Jika config tersedia, sheet dipilih berdasarkan source_workbook dan sheet_name. Jika config belum tersedia, converter melakukan discovery dan menulis .discovered-config.json.

4.3 Parse layout Kamus KPI

Workbook sumber dibaca sebagai layout block-style. Converter mencari header row, membaca KPI Impact, KPI Output, dan KAI, lalu menerapkan inheritance untuk cell yang terlihat seperti merged cell atau kosong di bawah baris induknya.

Aturan parsing penting:

  • Nilai placeholder seperti (blank) dianggap kosong.
  • Impact adalah parent utama.
  • Output menjadi child dari Impact.
  • KAI menjadi child dari Output.
  • Duplicate Output dengan judul sama digabung, weight dijumlah, dan KAI child direparent ke Output canonical.
  • Shared KPI Impact bisa dibackfill antar sheet berdasarkan judul jika salah satu sheet memiliki field yang valid.

4.4 Matching posisi dan company context

Matching posisi menggunakan normalized title, alias jabatan, company/workbook context, dan reference OM Production. Logic terbaru menjaga candidate list tetap tersedia agar reviewer dapat melihat opsi yang ditolak atau belum cukup yakin.

Spec update: strict position mapping berikutnya dipisahkan menjadi lookup structural PMID dan lookup non-structural PNID. Worksheet title harus menentukan scope terlebih dahulu; hanya mapping high_confidence yang boleh auto-map. Detail lengkap ada di docs/converter/position_mapping_logic_spec.md.
  • Alias umum seperti divhead, depthead, spv, corsec, dan variasi typo managr dinormalisasi.
  • Company context dari workbook dipakai untuk mempersempit kandidat, tetapi kata generik seperti regional atau title jabatan tidak boleh otomatis dianggap company.
  • Jika kandidat tidak unik atau confidence tidak cukup, config diberi scope mapping_conflict.
  • Conflict tidak menghasilkan row upload untuk sheet tersebut sampai override disetujui.

4.5 Rule PMID vs PNID

Rule utama: posisi structural wajib mengisi Position Master ID (Required) dan mengosongkan Position Nomenklatur ID. Posisi non-structural wajib mengisi Position Nomenklatur ID dan mengosongkan PMID. Dalam strict mapping spec, keputusan structural/non-structural dilakukan sebelum lookup ID: role seperti Group Head, Department Head, dan Manager masuk lookup structural, sedangkan role seperti Officer, Auditor, Analyst, Specialist, dan Staff masuk lookup non-structural.
Scope Identity output Catatan
structural PMID only Dipakai untuk jabatan struktural dari position master.
non_structural PNID only Dipakai untuk nomenclature/cluster non-struktural. Importer PMS yang expand PNID.
mapping_conflict Tidak ditulis ke upload workbook Fail-closed sampai reviewer approve override.

4.6 Normalisasi enum dan field upload

Field enum dinormalisasi sebelum ditulis ke upload workbook. Tujuannya agar value sesuai kontrak uploader PMS.

Field Allowed / logic
Polarity POSITIVE, NEGATIVE, NEUTRAL. Nilai seperti Positif dinormalisasi.
Period BULANAN, TRIWULANAN, TAHUNAN, SEMESTER, MONTHLY, QUARTERLY, WEEKLY.
Cascading DIRECT, INDIRECT, DUPLICATE.
Ownership Type SPECIFIC, SHARED, COMMON.
Weight (%) Ditulis sebagai numeric cell, bukan text, supaya Excel dan importer membaca konsisten.

4.7 Output row generation

Setiap row upload ditulis dalam 24 kolom resmi: 

IDKPI, Group, Direktorat, Posisi, Position Master ID (Required),
Position Master Variant ID (Optional), BSC Perspective, KPI Type,
Parent KPI ID, Parent KPI Title, Title, Description, Unit, Polarity,
Period, Formula, Weight (%), Cascading, Nature Of Work (KAI Only),
External ID (PKPI), System KPI ID, Ownership Type,
Position Nomenklatur ID, RKM Code ID

ID KPI dibuat per workbook secara incremental. Impact tidak punya parent. Output memakai parent Impact. KAI memakai parent Output.

5. Gating, Validasi, dan Acceptance Criteria

Gating saat ini: validator boleh menemukan workbook structurally ready, tetapi run tetap dianggap belum final jika masih ada mapping_conflict. Exit nonzero untuk conflict adalah behavior yang disengaja.

5.1 Gate converter

  1. Source ZIP harus dapat dibaca dan tidak mengandung workbook temporary Excel.
  2. Template upload harus memiliki 24 header resmi.
  3. Setiap worksheet harus resolved ke satu scope aman: structural, non_structural, neglect, atau mapping_conflict.
  4. Mapping conflict tidak boleh fallback otomatis ke PMID/PNID.
  5. Nama output workbook dibuat unik. Jika nama tabrakan, converter menambahkan suffix seperti - 02.

5.2 Gate validator

  1. Workbook output harus bisa dibuka tanpa ZIP corruption.
  2. Header harus persis sesuai template upload PMS.
  3. Setiap row upload harus punya tepat satu identity: PMID atau PNID.
  4. Structural row harus PMID-only.
  5. Non-structural row harus PNID-only.
  6. Parent KPI ID untuk Output dan KAI harus mengarah ke IDKPI yang ada.
  7. Batch final harus punya errors 0, termasuk mapping conflict 0.

6.1 Isi workbook override candidates

Workbook override candidates adalah dokumen utama untuk handoff review. Tab yang tersedia:

  • Summary: jumlah conflict per status.
  • High Confidence: kandidat paling aman untuk review awal.
  • All Recommended: kandidat recommended selain high confidence.
  • Ambiguous: conflict dengan kandidat banyak atau confidence belum cukup.
  • No Candidate: belum ada kandidat dari reference.
  • Manual Review: perlu keputusan reviewer karena signal belum cukup.
  • Override Candidates: tab utama yang dibaca script apply override.

7. Cara Menggunakan Converter

7.1 Generate awal dari source ZIP

Jalankan transform dengan source ZIP group, template upload, reference terbaru, dan output folder baru. Contoh pattern: 

python3 scripts/kpi_bulk_transform.py \
  --source "/path/to/KAMUS KPI GROUP.zip" \
  --template "input/KPI Upload Template.xlsx" \
  --mapping "output/production_position_reference_20260623_latest.json" \
  --output-dir "output/kpi_conversion_YYYYMMDD_groupX_latest_org"

Setelah run selesai, simpan .discovered-config.json karena file itu menjadi basis untuk review dan re-run berikutnya.

7.2 Buat recap dan review workbook

python3 scripts/build_conversion_recap.py \
  --output-dir "output/kpi_conversion_YYYYMMDD_groupX_latest_org" \
  --config "output/kpi_conversion_YYYYMMDD_groupX_latest_org.discovered-config.json" \
  --output "output/kpi_conversion_YYYYMMDD_groupX_latest_org_recap.xlsx"

python3 scripts/build_mapping_conflict_review.py \
  --config "output/kpi_conversion_YYYYMMDD_groupX_latest_org.discovered-config.json" \
  --reference "output/production_position_reference_20260623_latest.json" \
  --output "output/kpi_conversion_YYYYMMDD_groupX_latest_org_mapping_conflict_review.xlsx"

python3 scripts/build_mapping_override_candidates.py \
  --review "output/kpi_conversion_YYYYMMDD_groupX_latest_org_mapping_conflict_review.xlsx" \
  --output "output/kpi_conversion_YYYYMMDD_groupX_latest_org_override_candidates.xlsx"

7.3 Review dan approve override

  1. Buka file *_override_candidates.xlsx.
  2. Mulai dari tab High Confidence dan All Recommended.
  3. Pastikan candidate position, company, scope, PMID/PNID, dan source sheet memang benar.
  4. Isi kolom Approved dengan YES hanya untuk baris yang disetujui.
  5. Jangan approve baris ambiguous jika reviewer belum yakin.

7.4 Apply override ke config

python3 scripts/apply_mapping_override_candidates.py \
  --config "output/kpi_conversion_YYYYMMDD_groupX_latest_org.discovered-config.json" \
  --overrides "output/kpi_conversion_YYYYMMDD_groupX_latest_org_override_candidates.xlsx" \
  --output "output/kpi_conversion_YYYYMMDD_groupX_latest_org.reviewed-config.json"

Script hanya menerapkan baris dengan Approved bernilai YES, Y, TRUE, 1, APPROVED, APPROVE, atau OK. Structural override menerapkan PMID only. Non-structural override menerapkan PNID only.

7.5 Re-run converter dan validasi final

python3 scripts/kpi_bulk_transform.py \
  --source "/path/to/KAMUS KPI GROUP.zip" \
  --template "input/KPI Upload Template.xlsx" \
  --mapping "output/production_position_reference_20260623_latest.json" \
  --config "output/kpi_conversion_YYYYMMDD_groupX_latest_org.reviewed-config.json" \
  --output-dir "output/kpi_conversion_YYYYMMDD_groupX_latest_org_reviewed"

python3 scripts/validate_kpi_upload_batch.py \
  --output-dir "output/kpi_conversion_YYYYMMDD_groupX_latest_org_reviewed" \
  --config "output/kpi_conversion_YYYYMMDD_groupX_latest_org.reviewed-config.json" \
  --reference "output/production_position_reference_20260623_latest.json"

Batch final baru boleh dipakai sebagai kandidat upload jika validator selesai tanpa error dan tidak ada mapping_conflict tersisa untuk scope yang wajib dikonversi.

8. Handoff Review dan Backlog

Backlog utama bukan lagi struktur converter dasar, tetapi penyelesaian mapping. Urutan kerja yang disarankan:

  1. Review 42 high-confidence candidates lintas Group 1 dan Group 2.
  2. Review 59 recommended candidates tambahan.
  3. Resolve 88 manual-review/no-candidate blockers yang membutuhkan keputusan eksplisit.
  4. Resolve ambiguous conflicts dengan melihat workbook source, company context, dan OM reference.
  5. Apply override, re-run converter, lalu re-run validator sampai conflict 0 untuk scope yang wajib upload.
Jangan upload batch parsial sebagai full conversion. Output saat ini berguna untuk review dan validasi struktur, tetapi full upload membutuhkan penyelesaian mapping conflicts terlebih dahulu.
